# Independent routine speed validation

No paid inference, live mutations, fixtures, restart, deployment, authentication changes or credentials were used by this validator. Source and SDK tests use deterministic fake model/MCP inputs and real in-memory SQLite. Existing live evidence is historical, not acceptance of this new build.

## Phase 1 gate: PASS for existing evidence; BLOCKED for new live measurement

Independent `test_routine_speed_independent.py` verifies exactly six trace groups with one core tool and two model requests each, gpt-5.6-sol with reasoning none, matching durable correlation IDs/worlds, and request/confirmation/final-stream ordering. All six first forwarded stream chunks predate confirmation: those chunks cannot establish visible action-result delivery or browser paint. Confirmation epoch minus gateway arrival includes preparation; hook elapsedMs starts later and must not be substituted. Queue wait is below 10 ms in these unloaded runs. Baseline report's individual 3.709–6.746 s confirmed-action and 5.937–9.250 s gateway-stream durations are supported, with no meaningful cold/warm distribution. Historical traces lack per-operation context timings, distinct validation versus authoritative-readback epochs, receipt browser delivery and painted-result timing. New instrumentation supplies operation and delivery boundaries but has not been observed live.

Actual embedded source path remains browser ChatKit → authenticated gateway → Python Agents Runner → scoped read/action adapter → authenticated MCP → authoritative readback. Historical live receipts, independent inspect records and loaded build records support that path; mocks alone do not. Read-only current health before this task's builds reported core-actions-v1, started 2026-10-02T01:28:42.884Z; 28/28 startup disk hashes independently matched at that time. That is the baseline running process, not proof the subsequent build is loaded. Python installed packages independently verified: openai-agents 0.22.3, openai-chatkit 1.6.5, openai 3.22.1.

## Phase 2 gate: PASS for bounded offline lifecycle; BLOCKED for live acceptance

Real installed Runner.run_streamed and ChatKit stream_agent_response ran against a fake Model with no network. A sole authenticated pause command stops after one model request, delivers one stored factual summary, retains a complete function-call/output pair, and a fresh subsequent SDK turn receives that pair. Compound confirmed requests, uncertain outcomes and failures continue to a second fake-model request; uncertain/failed state does not produce success text. Other simple command families retain model continuation because no trustworthy sole-command completion contract is available. This is a documented limitation, not a claim all six families now use one request.

Receipt summary messages are persisted before stream delivery, distinct from a browser label. Complete tool exchanges use a custom converter to restore protocol items rather than treating labels as protocol history. Cancelled stream delivery after confirmation leaves the receipt summary and pair durable. Summary IDs deduplicate reconnect/replay. Failures and partial outcomes stay explicit; generic partial summaries do not enumerate successful subtargets, whose detailed receipts remain available to continued narration. Model repetition of receipt facts is discouraged by the permanent prompt, but compound/narrative model output is not mechanically guaranteed duplicate-free. Real-provider next-turn, browser reconnect and live cancellation remain untested.

## Phase 3 gate: PASS for bounded fresh context; BLOCKED for live acceptance

Independent TypeScript tests verify short/detailed equivalent phrasings receive identical initial context and exactly five relevant live reads, no actor or campaign excerpt expansion. Same-run scene change is reread; wrong world/user is denied before reads; revoked permission, released reconnect runs, and returned world mismatch fail closed. Existing independent overview tests verify content-hash change, world isolation, permission changes and campaign writer lock. Independent reads run concurrently, active-scene retrieval follows scene identification, and authorization is checked before/after reads and before return.

The implementation deliberately uses fresh turn-scoped snapshots instead of a cross-turn live-document cache because no reliable revision feed exists. Stable overview parsing is cached behind a fresh exact-source hash/visibility/lock check, and trusted catalog definitions retain the existing provider refresh behavior. No permission decisions become permanent grants. The requested explicit revision-aware cross-turn snapshot cache is deferred; source correctness does not depend on receiving document-change hooks.
