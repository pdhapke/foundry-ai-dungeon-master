# Acceptance fixture request guard (offline only)

Python now reads `AI_DM_ACCEPTANCE_FIXTURES_JSON` once when the sidecar application starts. Default `{}` grants no fixture allowance. Up to sixteen bounded entries bind an exact fixture ID to world, user, thread, trace UUID, a one- or two-request ceiling, and a timezone-qualified expiry within 24 hours. The internal authenticated gateway header carries only the fixture ID, never a browser/model-supplied ceiling. Unknown, expired and mismatched bindings fail before processing. Node configuration/header forwarding and browser-header rejection are credentials-worker-owned.

The existing SQLite database stores a durable consumed-request ledger keyed by the complete fixture scope. Existing RunHooks revalidate expiry and atomically consume one allowance before every provider invocation. Cancellation, a new hooks instance, retries or reconnect cannot reset consumed allowance. No automatic retry occurs (existing provider client remains `max_retries=0`). Runner additionally receives `min(existing configured max turns, fixture ceiling)`. Ordinary messages do not acquire fixture fields and retain the existing configurable normal ceiling, default fifteen. No model, summary or embedding requests ran during implementation.

Fixtures must be operator-configured only after the parent's exact budget approval. This machinery does not schedule or execute them. Stop at the first failure and restore/read back fixture state before continuing another approved trial; ledger exhaustion never authorizes another trace/fixture ID. Root's final runbook supplies the exact proposed prompt/model-call counts and restoration procedure.

Evidence: `prompt1-acceptance-budget-python-tests.txt` has three worker tests for one/two-request exhaustion, durable ownership across recreated hooks, expiry before consumption, default denial, exact binding, and body limits having no authority. `prompt1-budget-followup-python-final.txt` records twenty-four passing focused tests (overlapping preceding memory/context fixtures). Independent validator owns installed-SDK provider-call ceiling tests and retry verification. All tests set database `:memory:` before imports.

Runtime gate: this source is not claimed loaded until manual restart and startup artifact/config verification. Fixture configuration remains unset/default-empty during implementation. Summary maintenance generation stays disabled and separately budgeted.
