# Phase 5 panel and trigger inspection / bounded implementation plan

Read-only inspection, October 1, 2026. No implementation or live verification. Existing Phase 5 behavior is incomplete; this plan is not a validation PASS.

## Concrete gaps

- application.hbs retains Ask DM and Resolve Action as primary toolbar buttons and says context is supplied by the button. application.ts actions supply task prompts, not a permanent identity. Demote/remove both while retaining composer, cancel, model/connection controls and exact action review. Replace stale context notice with always-on bounded context and conversational setup/preparation explanation.
- hooks.ts listens only to a custom keyedAreaEntered event. No physical Region producer exists in this module. Installed Foundry constants define TOKEN_ENTER. Core RegionDocument._handleEvent routes physical events to enabled RegionBehavior documents; RegionBehavior invokes registered type events. Do not assume there is a generic global tokenEnter hook. Use a registered module RegionBehaviorType with explicit campaign key metadata after validating the supported installed API, or a separately verified supported behavior integration. Do not patch vendor methods or require every raw token move to start inference.
- automatic-triggers.ts coalesces by kind/document only and identifies events by that slot plus timestamp. Two different keyed areas entered by one token within 250ms collapse; same timestamp can collide. Include world/scene, token, keyed Region identity, revision and transition identity in a bounded stable event ID (hash if necessary). Coalesce repeats of the same event, not distinct entries. Current max IDs also diverge from shared context's 128-char ID limit.
- hooks.ts marks outgoing player turns in preUpdateCombat then consumes the marker in updateCombat. Remote observers cannot rely on their local preUpdate hook executing for another client's update. Snapshot previous combat round/turn/combatant ownership per combat, initialize on ready/create, compare on every update, handle round wrap and reordered/deleted combatants, and clear on combat/world lifecycle. Suppress combat initialization and backward navigation unless explicitly required.
- Door trigger accepts any ds=1 change with modifiedTime, without checking prior closed state, physical door type, scene, player ownership or initiating user. Capture previous state, only emit a closed-to-open physical door transition with an authorized player origin and relevant scene context. Decide explicitly whether a GM acting for the solo player qualifies.
- AutomaticTriggers.cancel exists but hooks never calls it. The setting gate runs at accept time, not timer dispatch. Disabling automatic events can therefore leave scheduled turns alive. World switch, disconnect, panel cancellation/close and setting disable must invalidate timer generation and queued automatic requests. Recheck captured world identity and settings immediately before dispatch.
- application.cancel invalidates its trigger queue and aborts requests, but does not cancel hooks' timers. A delayed timer can reopen the panel after cancellation/close. dispatchTrigger awaits mount/readiness without another generation check, so cancellation during readiness can still send. Add checks at each await boundary and distinguish automatic queue cancellation from unrelated manual turns.
- Server ChatKitTurns provides durable event recording, restart interrupted status and per-world serialization. Reuse it. It labels events via the requestId prefix as reviewed-hook-hint; that is browser input, not authoritative provenance. Do not let a claimed prefix/origin bypass permission or suppression policy.
- AI echo suppression reads options.aiDmOrigin only. Search found no marker producer in the MCP execution path. Local-api transactions.ts applies target.update(normalizedData) at lines766/885 without correlation/origin options; rollback also omits markers. combats.ts nextTurn/nextRound calls likewise do not propagate them. Existing transaction correlation receipts and movement correlationId do not automatically mark document hook events. Authoritative markers must be generated in trusted adapter execution and carried through bridge commands and Foundry update options/read-back receipts. A browser/model aiDmOrigin string alone is insufficient.

## Bounded ownership and contracts

Assign the panel/automatic lifecycle worker application.ts, hooks.ts, automatic-triggers.ts, index.ts, template and focused tests. Transfer those files explicitly. Shared trigger envelope and server provenance contracts require coordinator ownership or explicit handoff. Local-api is already dirty: any bridge marker change requires exact line ownership and preserved dirty inventory; do not sweep-format or rewrite its transaction module. If no narrowly authorized bridge marker path is safe, keep echo-prone mutations unavailable and report the gate blocked.

Capture event metadata (worldId, sceneId, source document/Region/token, stable revision, correlation) at intake, but server capability/world binding must remain authoritative. Browser scene/document references are hints requiring revalidation. Use server event identity across GM clients; an elected active GM can reduce duplicates but cannot replace durable deduplication. Cancellation must abort queued server ingress and never automatically retry interrupted inference or uncertain mutations.

## Required focused tests

Hook harness: actual registered hooks/behavior callbacks; two GM clients same event, distinct keyed areas in a rapid move, same Region exit/reentry, player vs NPC entry, malformed key, hidden/unconfigured Region, remote combat update without local preUpdate, round wrap, no-op/backward/init updates, closed-open door and no-op update. Verify event payloads and captured scene/world.

Lifecycle: disable after schedule, cancel during mount/readiness, close/reopen, disconnect/reconnect, world switch while timer/queue active, manual+event overlap, duplicate replay/restart and authoritative AI-origin echo suppression. Existing one timer test intentionally collapses distinct keyed areas and must change; it is not evidence of physical Region integration.

Separate live gate: approved isolated-world fixtures/reload and model budget. Verify loaded build identity, physical Region entry, remotely initiated combat turn, door event, multi-client dedup, AI document mutation marker round-trip, cancellation/reconnect and world switching. Deterministic hook mocks cannot prove these live behaviors.

Changed path: this plan only. No fixtures, config, credentials, vendor changes, live reloads or model calls.
