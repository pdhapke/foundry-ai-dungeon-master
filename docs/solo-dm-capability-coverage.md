## Authority and practical limits

Current server-issued ordinary GM world authority permits admitted typed world reads and non-destructive writes without repeated routine approval. Exact authenticated browser review remains required for deletion, ownership and embedded-array changes. Executable code remains excluded pending a separate restricted executor even after generic review. HP, doors, initiative, combat successor, plain chat, conditions and exact playlist sound state use bounded durable session actions. Exact token coordinates use admitted typed world Token updates with revision/origin/read-back; the dedicated movement session tool remains omitted pending its physical-Region/live gate. Canonical campaign resources retain campaign proposal controls. GM world settings, permissions, Users and world-owned packs/assets are authorized in principle; missing method-specific/security-selected-key/root adapters are implementation gaps rather than blanket permission denials. Host/client identity, outside-world packages, credentials and executable code need separately scoped controls.

WorldFiles supplies six semantic tools independently of provider descriptor counts: `ai_dm_list_world_files`, `ai_dm_read_world_file`, `ai_dm_write_world_file`, `ai_dm_make_world_directory`, `ai_dm_delete_world_file`, `ai_dm_recover_world_file`. The server alone supplies the active-world root. Production writes remain disabled until deployment privacy verification explicitly supplies its callback. Deletion and recovery require durable exact browser review; runtime/databases/packages/credentials stay outside the file facade. Direct `data/campaign` writes are blocked for campaign controls. Browser reviews are bounded separately from model context; models receive summaries, not duplicated recovery journals.

Offline deterministic gates validate source adapters and browser contracts. No live loaded-build identity, new runtime advertisement or actual receiver playback is asserted. Interrupted effects stay uncertain and never silently repeat.
