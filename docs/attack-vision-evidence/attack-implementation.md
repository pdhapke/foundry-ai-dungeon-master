# Bounded native attack implementation

Implementation boundary: single dnd5e 6.0.3 attack activity, exact scene/attacker token/actor/item/activity/target token identifiers. Both actors must still exist in the current active scene and the current exact requesting GM must remain active. Native system data supplies bonuses, formulae, critical threshold, automatic roll modifiers and damage types. No parallel rules engine was added.

Reviewed installed source is `Data/Data/systems/dnd5e/dnd5e.mjs`: AttackActivity.rollAttack at line 21441 returns native D20Rolls and owns ammunition/thrown consumption; inherited rollDamage at 18244 derives native damage/critical options; AttackMessageData.evaluatedTargets at 86349 owns target hit/miss including fumble/critical priority; Actor5e.applyDamage at 43218 owns native damage adjustment, temporary HP and HP update, calling calculateDamage at 43288. Exact line numbers refer to the inspected installed artifact. Independent validation also evaluates the exact installed target getter, separate from mocked integration tests.

Protocol `attack-actions-v1` uses `foundry_attack_state` for on-demand identifier/options discovery and `foundry_attack_confirmed` for execution. `action.mode=roll` rolls attack and, for a hit with no unresolved reaction, native damage. It never applies HP. `action.mode=apply` references priorAttackRequestId and applies saved damage; it never rerolls existing evidence. A native reaction activity on attacker or target produces an explicit decision ticket after the attack and before damage. Only an authenticated direct human decision may supply that ticket through the AI policy boundary; the model cannot waive it. Native cancellation and ambiguity remain explicit.

Persisted evidence includes attack/damage roll identifiers, totals/formula/results, native hit/critical, damage types/properties, damage rolled versus applied, observed HP/temporary HP, native adjusted damage and resource snapshots. damageApplied is actual HP loss plus temporary HP loss, not raw rolled damage. Native cancellation is distinguished from immunity with calculateDamage/applyDamage hooks and authoritative HP observation. Temporary hooks attach existing mutation origin markers to scoped native Actor/Item updates and are always removed.

The server uses the existing authenticated exact-GM bridge, shared routine mutation lane and shared uncertainty fence. Browser execution also serializes attack operations. A dedicated private JournalEntry stores a bounded durable ledger (default ownership NONE, no player ownership overrides). This replaces a proposed world setting, which would broadcast private mechanics. A pending claim is acknowledged before a roll/resource side effect; attack evidence is acknowledged before damage rolls; application is claimed before native HP effects. Existing IDs replay recorded outcomes only; changed arguments fail. Pending or uncertain records block fresh attack IDs across browser reloads. A second apply cannot claim the same rolled damage. Capacity exhaustion fails closed rather than evicting replay protection.

The bounded first implementation rejects activity usage/spell-slot consumption, spell activities, effects/behaviors, ambiguous damage types, weapon mastery effects, and ranged long-range/cover workflows. Native ammunition/thrown consumption is supported when explicit choice information is available; resources are observed before/after and duplicates do not consume twice. Multiattack/multiple targets are not supported. Native rollAttack does not enforce target legality, melee reach/range, attack path or cover. These remain GM adjudication and are explicit receipt limitations; this implementation does not claim automatic range/cover legality. Reaction trigger detection is conservative because the reviewed native system exposes reaction activities but no general trigger resolver.

Reconciliation is inspect-only: scoped recent receipt summaries and durable ledger evidence are available. There is no automatic clear/retry for ambiguous outcomes, nor an unsafe reapplication endpoint. Manual repair of a demonstrated ambiguous fixture must be coordinated with its recorded evidence. A changed target HP refuses application. Changed AC can be reevaluated from serialized native D20Roll evidence without rerolling; if reconstruction is unavailable it fails closed.

Installed source getter validation separately passes. These are source/mock integration checks, not live acceptance. Applicable typechecks pass; final builds/full tests and independently approved dedicated live fixture checks belong to the parent gate.

New production files are MCP shared/src/attack-actions.ts, module/src/commands/attack-actions.ts, and server/src/endpoints/attack-actions.ts. Existing shared/index, module/index and endpoints/index integrate them. They must be included in loaded build identity checks before live use.

Independent validation later demonstrated two narrow defects and their repairs: native Roll.toJSON returns an object while fromJSON requires a string, so the durable native roll is now JSON.stringify serialized; FormulaField usage limits such as `@prof` are nonempty resource requirements and now fail before any roll instead of bypassing a numeric comparison. The expanded focused suite passes 15 tests (six implementation, nine independent), including Shield-style AC reevaluation with no reroll and formula-based resource rejection. Target actor identity, both token positions/elevation, and source item revision also bind pending application; stale substitutions fail closed.
