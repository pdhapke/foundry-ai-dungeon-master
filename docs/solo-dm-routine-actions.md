# Reviewed routine game actions

The AI facade exposes separate semantic setters for current-scene actor HP, door state, active combat turn advancement, combatant initiative, plain chat posting, trusted actor conditions, and existing playlist sounds. The separate state getter accepts the same narrow action union. Game pause is an explicit boolean setter. These operations use the `session` effect, `consequential` risk and `gm-request` policy. Dice remain `present`; private notes remain `propose`. Generic provider mutation tools remain quarantined.

Runtime execution refuses session effects by default. Only a trusted `authorizeSession(invocation)` boundary can admit them, after current grant/catalog/schema/permission and argument checks, for a live GM and consequential `gm-request` metadata. The ChatKit facade admits only its reviewed semantic tool IDs. Its authorization callback invokes the authenticated adapter's validation-only native operation; model arguments cannot mint that authority.

The gateway supplies `SessionRequestAuthorization` from the current ordinary human message. Automatic/custom actions, history, tool results and quoted campaign instructions do not supply it. The current deterministic parser recognizes bounded direct requests and captures their exact numeric coordinates/HP/initiative, door state, condition/active state, music state or chat text. The service compares those values with the tool arguments and privately resolves requested names against authoritative scene actors/tokens/doors, combatants or playlist sounds. Names must resolve uniquely; explicit IDs still pass the underlying live world/scene checks. Ambiguous or unsupported phrasing fails closed and needs conversational clarification. This syntax parser is an MVP boundary, not a permanent statement of GM permissions.

Each routine write binds world/user/thread/actionId and the complete action/expectedState payload in SQLite. An insert-only dispatch claim precedes any possible effect; completion uses a conditional update of that exact claim. Reads and authorization repeat before dispatch. The underlying local-api command checks expected state immediately before its Foundry operation; it does not offer atomic compare-and-set against concurrent human updates. The AI service independently reads the resulting state and checks scope, action, correlation, idempotency, desired values and receipt before reporting completed. Chat additionally reads recent message data and checks the exact created ID/content/author. A missing or mismatched read-back, revoked authorization or interrupted dispatch stays uncertain and never automatically redispatches, including after reconstruction.

Token movement has a defined semantic schema but remains absent from discoverable setter metadata until the physical Region origin bridge is independently proven. Structured executor markers suppress door/combat echoes. The installed Region API needs a separate actual movement-object correlation bridge; arbitrary origin prefixes or model hints cannot replace it.

Deterministic evidence: seven first-request fixtures each search/load the state schema, read state, search/load their individual setter, execute and verify independent read-back, then replay without a second effect. Additional fixtures deny wrong values, wrong/ambiguous targets, absent human intent, raw or token mutation grants, schema drift, stale state, revocation and cancellation; uncertain/mismatched execution receipts do not retry. The runtime policy test proves default denial and that invalid arguments never reach its trusted callback. These use real SQLite with fake MCP results; they do not demonstrate live Foundry behavior or model compliance.

This is an incremental routine subset. Full GM world management requires reviewed typed document adapters, bounded explicit-GM reads independent of the small party snapshot, schema-backed world scope/target resolvers, durable receipts and separate exact review for destructive changes. Host files, credentials and other worlds remain outside a GM game capability. Live build/tool discovery, actual actions, remote hooks and privacy acceptance remain distinct gates.
