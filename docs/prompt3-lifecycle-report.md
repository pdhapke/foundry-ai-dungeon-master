# Prompt 3 bounded status lifecycle

Implemented in `status-refresh.ts`, `transport.ts`, `controller.ts`, and `panel-preparation.ts`. No runtime, provider inference, campaign changes, publication, or rebuild was performed by this worker.

`StatusRefresh` accepts a model-free async request that completes on its actual status reply, an authorization eligibility predicate, and injectable scheduling. `open()` and `refresh()` share a pending request; successful replies are cached for one second. `invalidate()` shares pending work and records one fresh follow-up for meaningful changes. Failures retry twice at 1 and 3 seconds; concurrent demands do not bypass scheduled backoff. Closing cancels timers and status requests, fences late completions, and invalidates the short cache. It does not touch response streaming, tools, or provider authentication.

Transport shares this path across initial GM connection, panel lifecycle, manual recovery, model changes, and trusted OAuth completion. Matching request IDs complete discovery; unsolicited provider status still applies. Retired discovery IDs are bounded to 64 and late replies are ignored. Provider mutations (`model.select`, `signout`, `signin.begin`) first cancel/retire active discovery so its older response cannot overwrite newer authoritative provider state. Foundry credential renewal suppresses provider discovery during its synchronous connected notification, preserving the existing no-model-discovery/no-replay invariant. OAuth fallback has at most six checks with exponential delays capped at 15 seconds; the existing source/origin validated completion message remains primary. Exhausted status failures show concise manual recovery guidance.

Application integration API: `controller.openStatusPanel()` on panel open/reconnect; `controller.closeStatusPanel()` on panel close; `controller.refreshChatGptStatus()` on meaningful settings/auth invalidation or explicit recovery; `controller.reconnect()` for disconnected/failed local authentication. Manual recovery disconnects and reconnects the existing transport without inference. Meaningful refresh during a pending discovery may produce exactly one subsequent check; plain repeated opens do not.

`PanelPreparation.refresh()` shares any current preparation request rather than cancelling an opener, otherwise invalidates the cache and checks again. Identity/settings invalidation retains the existing abort fence. Safe corrective messages distinguish context admission, campaign storage protection, expired Foundry authentication, and GM authorization. Backend error text and blocker contents are not echoed.
