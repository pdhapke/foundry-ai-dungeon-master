# Prompt1 Python implementation and offline gate

Python ownership: `chatkit-server/app.py`, `working_context.py`, focused memory tests and existing fixture updates. No TS changes, model requests, summary generation, embeddings, automatic-event changes, runtime restart or private campaign authoring were performed.

The current SQLite store already owns the durable ChatKit transcript, isolated by exact world/user and thread. Confirmed receipts and complete hidden tool exchanges already persist there. The previous working-context path loaded only twenty items and trimmed serialized characters. It now loads the full uncompacted tail (bounded at 5,000 items), validates complete call/result protocol, and refuses capacity overflow before Runner rather than dropping unresolved messages. No Agents SDK session history is added: this remains the one model-input owner and existing agent loop.

Model input includes permanent instructions/play rules and the compact trusted recipe index, bounded versioned historical summary when explicitly published, complete recent history, and the existing authenticated `initial_context` campaign overview/index/catalog/live snapshot. Detailed campaign tools remain on-demand; `dm_history_search` adds literal bounded retrieval from only the authorized current thread, with at most five 1,024-character excerpts, source IDs/revisions and an explicit historical-data classification. `dm_recipe_read` accepts only four packaged IDs and cannot read arbitrary campaign paths. Preparation reuses Node's existing context builder/cache; Python adds no competing credential/context cache and never reuses an execution capability.

The token bound is conservative UTF-8 serialized bytes plus structural overhead, including actual installed tool names/descriptions/schemas. At audit the core schemas bound is approximately 22,383 and permanent instructions/index approximately 14,111 bytes. The total window is 65,536 only for exact `gpt-5.4`/`gpt-5.4-2026-03-05`; parent verified the official model specification at <https://developers.openai.com/api/docs/models/gpt-5.4>. Other model IDs retain a conservative 32,768 window and can refuse the full core catalog. 8,192 additional tokens remain reserved for tool results/output. Representative actual-schema fixtures fit the verified window; a 32KB context response can still exceed this intentionally conservative bound and is refused with an actionable ChatKit error. Provider-specific acceptance remains a live gate, not proved by the public model specification.

Summary maintenance is an internal application-managed publication primitive, not automatic inference. `publish_summary` requires source messages, a bounded 8KB summary, a coverage watermark, expected complete transcript revision and expected summary version. It validates the covered tool protocol, acquires a SQLite write transaction, and rechecks after asynchronous conversion. Delayed/concurrent publication cannot replace newer evidence or summaries. Failed generation is never invoked here; failed/stale publication preserves the last valid summary and uncompacted tail. Original item bodies before correction and all summary versions are archived in the same database. Corrections to covered original evidence invalidate summary coverage and restore the original tail to model input. No transcript compaction/deletion is performed.

SQLite defaults now resolve outside Foundry's publicly served Data tree at checkout `.runtime/foundry-ai-dungeon-master/chatkit.sqlite`; explicit paths within this installation's static Data tree are rejected (exact SQLite `:memory:` fixtures are exempt). On configured legacy migration, SQLite's backup API copies committed state from a read-only legacy connection only if the destination is absent or consists entirely of known empty transcript tables; it does not replay gameplay or overwrite nonempty/unknown storage. A durable migration marker prevents later empty remigration. Earlier fixture imports created an empty real destination, now explicitly handled by this migration gate; final test commands use `AI_DM_CHATKIT_DATABASE_PATH=:memory:` before imports. Node config and launch environment changes are parent-owned. Live loaded-path verification and manual restart remain required. Existing campaign file writes remain fail closed without a validated private-serving deployment; memory changes do not enable them.

Timing now emits a scope UUID and scoped monotonic elapsed value on console as well as durable traces. Hook-local elapsed fields are renamed `hookDurationMs` so their origins cannot overwrite scope elapsed. Prepared-context duration remains measured independently from model duration.
