After the one allowed model call and confirmed tool, installed Agents SDK reaches max_turns1 on its next iteration and raises MaxTurnsExceeded. The uncaught exception reaches ChatKit's default stream handler, which emits generic stream.error with allow_retry=true. The exact live exception class was not captured, but a real installed-SDK fake-model reproduction with identical prompt/arguments and one-call cap demonstrates this path after durable pair/receipt commit. No SDK dependency change needed.

Repair: app.py imports MaxTurnsExceeded and handles it at respond's streaming boundary, yielding explicit custom ErrorEvent with allow_retry=false and full-request completion unconfirmed. SDK turn/call/output limits stay unchanged. Confirmed receipts and complete tool-call/result pairs remain persisted and visible. It does not suppress the error as a successful full request, infer compound completion from one action, or broaden/duplicate the trusted server parser. Matching trusted receipt-only contracts still finish cleanly in one request.
