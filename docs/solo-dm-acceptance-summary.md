## Implemented behavior

Ordinary chat and application observations use permanent solo-dm-v6 identity in
the existing single Python model/tool loop. TypeScript supplies authoritative
world/rules/game/party context, a separately bounded overview and attributed
indexed Markdown retrieval. Explicit canonical party references permit verified
off-scene actors; missing/partial assignments are surfaced. Existing Izzy content
is preserved with explicit legacy compatibility.

Typed campaign read/proposal/status tools and exact human review support
revision-bound, recoverable overview/index/resource batches, separate drafts and
durable completion receipts. Assistant narration cannot approve canon. Production
private persistence remains disabled: server wiring supplies no verification
callback, and the current direct Foundry Markdown route is public. A protected
deployment and supported reviewed enablement mechanism remain approval-required
future work; there is no undocumented environment toggle or authorized bypass.

Bounded discovery searches trusted descriptors, loads selected schemas and issues run grants. Verified ordinary GM turns carry active-world role authority rather than a small command whitelist. The expansion adds pause and routine session setters, typed top-level and embedded world document control, and authored world-file access. Preflight, live reauthorization, durable claims and separate authoritative read-back govern completion. Destructive/ownership changes use complete digest-bound browser review; model narration cannot approve them. Unknown raw MCP, executable code, host credentials and server administration have separate boundaries. Every capability disposition is recorded in [coverage](solo-dm-capability-coverage.md).

The panel keeps the ordinary composer, connection/model controls, cancellation and exact proposed-action review. Optional automatic observations cover keyed physical Regions, door opening and completed player turns. Durable ingress/world queues deduplicate and serialize turns. The physical Region origin bridge correlates actual core movement-object identity with trusted executor metadata; mocked hooks and installed source inspection are distinct from live proof. Current expansion validation remains in [capability validation](solo-dm-capability-validation.md) and the [ledger](solo-dm-ledger.md).

Companion authentication does not protect that static route. See the [privacy
proposal](solo-dm-privacy.md) for supported reverse-proxy denial plus backend/
local-browser bypass restrictions; do not patch vendor middleware or rely on
obscure filenames. Privacy protection/configuration, verification/enablement
wiring and live direct-file tests require explicit approval.

read-back; actual Regions/doors/remote combat/multiclient deduplication; origin

behavior. Existing Izzy resources and unrelated dirty bridge files remain outside
