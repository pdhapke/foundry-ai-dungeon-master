## Separate proposals requiring scope approval

No new mutating workflow is implemented here. Proposed start, round, map and detection coordinators would need typed bounded inputs; current world/user/role checks; shared world ordering; stable operation IDs; durable per-step receipts; revision checks before each commit; pending human choices; cancellation and uncertainty fences. They are not atomic: retain partial completions and never retry dice/resource consumption under a fresh ID. Round proposals must store boundary/roster/progress and reconcile initiative changes without replay; detection proposals must store triggering event/actors/revisions and distinguish notice/activation/effects. Map proposals must not lock world ordering while external acquisition runs.
