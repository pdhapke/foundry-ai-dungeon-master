# Prompt 2 deterministic preparation jobs

## Native production contract audit and durable handoff

The current `foundry-local-api/docs/openapi.json` transaction preflight/execute manifest permits top-level `JournalEntry` and `Item` only; embedded creation is `JournalEntryPage` under `JournalEntry`. It excludes Scene, Token and Note. Direct `foundry_create_scene` and `foundry_update_scene` accept generic native document data, but direct scene updates expose no atomic expected-revision parameter. `ChatKitWorldDocumentActions` provides before-source revisions, durable claims and read-back, and may immediately dispatch create requests. Those primitives do not prove a coherent atomic map + token + private-note population commit.

`NativePreparationReviewQueue(db,authority)` now persists exact bounded private proposed `foundry_create_scene` requests in the existing private operational SQLite database. `stage(caller,job,areaId)` preserves stable preparation flags, inactive/non-navigation/default-denied scene settings, token actor isolation and explicit footprint fields. `get` retrieves the same-world GM-only package; `review(caller,id,approvalId)` requires server-held human review of the exact package digest and fresh source revisions. Private GM notes and trap references remain in a separate authenticated package field, never in the proposed scene request. `dispatch` always rejects with explicit contract blockers, even after human review. No request is sent to the existing world-document executor and no live document is created by this queue.

An independently reviewed single native draft Scene create remains the supported primitive path through the existing authenticated world-document workflow. Nested token creation, native grid origin mapping, inactive-scene secrecy and coherent population commit require selected-system fixture validation and a reviewed native atomic contract before production execution. This worker does not expand the transaction engine or claim those contracts are implemented. The callable area/map/population preparation stages remain functional reviewable proposals.

Six model-free tests pass, including private durable native review package idempotence, world/secrecy bounds, exact human review, stale-source rejection and blocked dispatch.

Implemented `shared/src/preparation/types.ts` and `server/src/preparation-jobs`. These are resumable callable services, with private persisted proposals, not paid generation. All operations revalidate GM authority and exact world scope through the injected authority. The injected revision reader must return the current selected-world source manifest. No player status projection is offered: jobs, titles, traps and future destinations are GM-only.

`PreparationJobService.create(caller,input)` accepts a stable request ID, selected world, 1–8 explicit area IDs, 1–64 source revisions, outline/encounter depth and desired records/map/population readiness. Repeating the identical request returns its persisted job; changing its inputs requires another request ID. `status`, `pause`, `cancel`, and `resume` take caller and job ID. Resume and every preparation stage reject edited or deleted source revisions. No polling or inference is scheduled.

`prepareAreas(caller,id,sources)` conservatively reuses supplied existing area records with matching source revisions. `prepareMaps(caller,id,candidates)` stages authorized assets with provenance/license, explicit grid settings, profile and at least three artwork/grid-coordinate reference measurements spanning opposite map regions. The workflow fits uniform spacing/origin itself, verifies configured native grid against fitted values, and rejects distortion under caller-specified tolerance; asserted residuals cannot bypass this check. `preparePopulation(caller,id,proposals)` stages bounded native actor references, token footprints, private note record references and manual/unsupported traps with private bounded regions, trigger/detection conditions, consequences, and explicitly inactive state. Token elevation, disposition and actor linkage are validated when provided. Stage content is immutable per request; repeat identical content is idempotent. GM must establish source authenticity through authenticated source reads; imported strings remain proposal data. No alias deduplication, geography inference or mystery generation occurs here.

`FilePreparationJobStore({protectedRoot,publicDataRoot})` requires an existing server-configured private directory outside actual Foundry static Data and rejects symlink file entries. It atomically replaces bounded JSON files and compares revisions. This is a single-process cooperative writer store; administrators must not edit directories concurrently. It does not touch the existing campaign originals. Alternatively inject a `PreparationJobStore` backed by the existing protected campaign repository.

`applyReviewedDraft(caller,id,{areaId,sceneId,expectedSceneRevision,approvalId},adapter)` is an executable injected native apply boundary. The adapter resolves external human review covering the exact proposals; the model cannot issue approval. It accepts only same-world dedicated inactive preparation fixtures and exact scene/source revisions. Adapter must atomically recheck those preconditions and use native system schemas. Its persisted idempotency receipts permit recovery after a scene write but before job-receipt persistence. This service never activates a scene, moves players, starts combat, modifies shared actors, or triggers traps. A real production native adapter is not bundled and no live mutation was executed. Root integration must fail closed when no adapter is configured.

Map proposals refer to Prompt 1 battlemap preparation and existing `dtt_get_status`, `dtt_pan_battlemap`, `dtt_scale_battlemap_to_physical` interfaces, without calling them during staging. `auditUniformGrid` fits X/Y baked-grid spacing and origins from measurements spanning at least half of both image dimensions, compares a uniform overlay against every landmark, and reports residuals under an explicit tolerance. Distortion/rotation produces failed alignment rather than asset stretching. `geometryMigrationImpact` produces reversible coordinate proposals for tokens/walls/doors/notes/lights/traps and explicitly requires coherent native geometry review. It never applies a transform. Architecture dimensions and TV acceptance remain independent pending checks.

Readiness booleans describe successful proposal stages only. Visibility configuration, operational trap mechanics, TV/player acceptance and live acceptance remain false. Maps are not imported scenes and annotations are not operational traps. Actual affected current scene identification, visual before/after overlays, user tolerance agreement and TV validation remain manual acceptance gates.

Validation: shared build, server typecheck, and five focused model-free tests pass: repeat idempotence/no spend/world isolation; cancellation/resume/stale source rejection; map drift/token footprint rejection; externally reviewed inactive native fixture apply and duplicate receipt handling; multi-edge uniform-grid fitting/distortion and reversible geometry impact. Independent validation is performed separately by the orchestration owner. No runtime restart, inference, image generation, budget consumption, publication or active-campaign alteration occurred in this worker.
