# Phase 2: authoritative receipt delivery

Implementation gate: existing Python checks PASS (27); focused independent SDK lifecycle checks PASS (4), independent final gate pending. No paid inference, server restart, live game mutation, or live acceptance was performed.

Installed dependencies inspected directly: openai-agents 0.22.3, openai-chatkit 1.6.5, openai 3.22.1 (pinned requirements and installed sources). Agents supports callable `tool_use_behavior` returning `ToolsToFinalOutputResult`; function lifecycle hooks receive `ToolContext` including call ID and arguments. ChatKit merges `AgentContext.stream` thread events with runner events; ChatKit does not manufacture an assistant message from arbitrary final_output. Official cross-check: https://developers.openai.com/api/docs/guides/custom-chatkit . Exact behavior follows installed source.

After authenticated execution returns, `PauseTimingHooks.on_tool_end` persists a complete native function-call/result pair, then a receipt-derived assistant message, then streams a completed message event. Summaries use authoritative observed state, never requested arguments. Failure, denial, partial and uncertainty explicitly disclaim confirmed completion; malformed receipts produce no success. Receipt messages have stable identities scoped to world, user, thread and correlation ID, avoiding duplicate stored/delivered summaries on retry. State observations remain separate from stream completion.

`ReceiptHistoryConverter` restores stored pairs as valid Responses function_call/function_call_output inputs for the next turn. Pair boundaries survive context trimming. Pair identities are scoped to the SDK call ID; identical replay reuses the pair, while changed content under the same ID stops for reconciliation. Existing ChatKit thread persistence remains responsible for ordinary model messages. The receipt is persisted before browser delivery, so disconnect/reconnect preserves the factual result. Cancellation still cancels the runner; execution receipts remain durable in the existing authoritative backend.

Safe second-model omission currently applies only to the existing authenticated exact sole pause-command path, and only one confirmed pause tool result. Compound, narration, failures, uncertain results, other controls and discovery continue through the model. SDK supports omission, but the application has no trustworthy general semantic completion contract: treating the first tool as completion or trusting a model completion flag can truncate compound requests. No new wording heuristic or classification inference was introduced. Direct controls already bypass model inference.

The permanent DM prompt instructs continuation to avoid repeating the displayed summary while continuing requested narration and remaining work. Exact duplicate receipt delivery is mechanically deduplicated; generative paraphrase repetition still requires manual live validation. No source-side latency claim implies browser rendering or paid model latency improvement. The potential savings are receipt visibility before acknowledgement and one model request for the narrow confirmed pause path; measured live savings remain unverified.

Initial context now uses the context worker's `initial_context` contract for both typed and custom action entry points, independent of wording. Prompt policy version remains solo-dm-v8-core-actions; compare exact health promptDigest and codeDigest with saved files after normal restart.
