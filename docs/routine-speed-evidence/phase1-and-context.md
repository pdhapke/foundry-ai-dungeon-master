Initial authorization is 24–44 ms. Queue excludes that authorization. First executable tool timing begins at model request, not browser send or gateway arrival. MCP measurement bundles validation, execution and authoritative acknowledgement; separate backend validation/readback durations were not recorded and are unknown. Preparation operation durations were also not recorded. Sum of parallel operation durations must not be treated as preparation wall time.

The gateway's “first-visible-stream-chunk” means first proxy write; it is not a measured paint or a confirmed-result event. Confirmed result browser delivery and actual visible canvas/chat update are unknown. Python assistant completion precedes final proxy completion by roughly 0–2 ms. Removing the second model can save acknowledgement time (2.078–3.712 s in these samples); it cannot retroactively improve action completion. One sample for each different command supplies no reliable median/tail or before/after claim. The rollout reports unpause first after restart and other commands in a warm process; caches and cold/warm conditions were not independently controlled. Narration was not measured.

The direct door shortcut record reports confirmed door state with the model count unchanged at twelve; it supplies no comparable arrival/render duration. Source path is browser ChatKit custom transport -> authenticated gateway -> Python ChatKit/Agents loop -> scoped read adapter -> native TypeScript service -> authenticated MCP -> Foundry browser backend -> authoritative receipt. Independent archived validation covered embedded chat, stored history and fixture state, separate from deterministic tests. Archived loaded-build records show policy core-actions-v1, prompt solo-dm-v8-core-actions, matching Python digest and all recorded Node/browser artifacts. These records establish the historical build, not the current loaded build after these edits.

Detailed wording previously fell outside explicitSessionRequest and therefore Python selected full `context` rather than `control_context`. Full context serially fetched world, scenes, active scene, system, combat, up to sixteen party actors, and campaign excerpts. That choice depended on wording even though execution used identical authoritative services.

All initial preparations now use `initial_context`: bounded campaign overview, current world/system, active scene/token identifiers, assigned party identifiers and combat identifiers. Four independent live reads run in parallel; the active scene read follows scene selection. No actor state or campaign excerpt expansion occurs. Missing actor/scene/rules/campaign details remain available through existing on-demand tools. Permanent DM instructions stay in Python. GM-visible token information is explicitly not player knowledge.

Snapshot safety: a fresh snapshot is scoped to the authenticated run/world/user and fetched on every preparation, including repeated reads. Permission is checked before and after every MCP read and at final return; execution checks are preserved. There is no mutable document cache to survive world switches, reconnects, permission revocation or missed update hooks. The existing stable overview parsing cache validates canonical root, transaction locks, source hash, metadata and visibility every use. Catalog refresh remains live. A cross-turn live snapshot/tool-definition cache with explicit document/system/schema revision notifications is deferred: the present adapter has no reliable revision feed. It must not be replaced with a TTL or cached authorization grant. This is an explicit scope limitation, with fail-closed behavior preferred over stale reuse.

New context-timing events contain traceId, hashed run correlation, operation, step, wall timestamp, duration and outcome only. They separate catalog refresh, source hash/parsing, permission calls and each MCP read; no credentials, prompts or document bodies are logged. Gateway also separates queued authorization and direct action queue/execution/proxy write. Backend validation/readback and browser rendering still require dedicated instrumentation/live observation. Independent context gate PASS for implemented fresh-snapshot behavior; full live performance acceptance remains BLOCKED until the manual checkpoint and approved inference allowance.
