# Prompt 1 recipe resources and executable gaps

2026-10-03 follow-up source audit. This document changes no code or runtime. All four required definitions are delivered as packaged, versioned policy in `chatkit-server/recipes/`; all four remain `partly-supported`. A retrievable recipe is not an executable workflow or an execution grant.

## Verified integration

Current `chatkit-server/app.py` loads index/details into immutable startup bytes and publishes a startup recipe-manifest digest. `prepared_instructions()` includes the trusted compact index; `dm_recipe_read(recipe_id)` accepts only `start-combat`, `combat-round`, `surroundings`, `battlemap`, and performs no campaign-file access or mutation. Actual implementation permits one detail read per response, stricter than the resource's one-distinct-detail upper bound. Index4096/detail8192 UTF-8 byte ceilings are enforced. These bytes are conservative token ceilings, not tokenizer measurements.

Ordinary response preparation obtains the existing authenticated `initial_context` snapshot, not a second world cache. `working_context.assemble_input()` accounts for permanent instructions/index, actual serialized tool schemas, untrusted summary, recent complete conversation and authorized snapshot with8192 reserve. `PauseTimingHooks.on_llm_start()` rechecks accumulated input and current schemas before each provider request. Current configured known gpt-5.4 path uses65536 conservative allocation; unknown model paths use32768 and refuse overflow. Neither configuration nor source inspection establishes live plan-provider acceptance or latency. The recipe index does not grant any catalog capability; current authorization/state checks remain authoritative.

State and agency remain live responsibilities: recipes stop at player turns, required player rolls/reactions/choices, ambiguous targets, unsupported mechanics and uncertainty. They do not grant permission to skip a player, reroll, replay damage, advance beyond a boundary, invent a trap or substitute a GM view. Each confirmed primitive outcome is factual evidence for that primitive only. A compound request remains incomplete until all requested supported steps are confirmed or an explicit stop is reported.

## Tight acceptance scope

Any separately budgeted live acceptance may demonstrate supported primitive subsets with dedicated reversible fixtures: combat read/explicit missing-only initiative/start where current grants permit; one supported NPC attack/application and advance stopping at player; exact connected-player permitted observation with unknown NPC/trap outcomes reported; draft scene/native-grid readback and targeted viewport acknowledgement. These are not full recipe acceptance. A disconnected player, absent grant, unresolved choice or proposed coordinator stops that scenario rather than triggering fallback machinery.

Full round resume, duplicate whole-workflow safety, bidirectional detection/trap activation, and live TV/physical calibration remain unaccepted unless their missing dependencies are separately approved and implemented. Image generation, summaries/compaction/embeddings and test inference require exact separate allowances. This follow-up consumed none, performed no runtime mutation, and did not enable automatic events.
