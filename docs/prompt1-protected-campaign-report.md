# Protected campaign source implementation

Offline followup, 2026-10-03. No production migration, restart, inference, original deletion or asset mutation was performed.

`ProtectedCampaignOptions` identifies an absolute server-owned `protectedRoot` and the actual `publicDataRoot`. Validation rejects a root inside Foundry public Data, redirects/junctions and non-directory roots. Deployment provisioning and loaded-runtime verification belong to startup integration. Existing account filesystem permissions remain the administrator's responsibility; this establishes an application-level location outside Foundry's static route, not an OS ACL claim.

`WorldCampaignContext(worldsRoot, options)` reads exclusively from `protectedRoot/<world>/data/campaign`. There is no fallback to public legacy campaign files when protected content is missing or invalid. Existing parser/index caches, visibility/canon filtering, budgets, source hashing and `campaign://<world>/<relativePath>` identifiers remain intact. The authenticated adapters continue to supply live-authorized principals and check authorization before/after disclosure. This class is a filesystem/data projector, not an independent authentication service.

`CampaignStorage(worldsRoot, authority, maxFileBytes, maxBatchBytes, options)` uses the same protected layout and existing transaction journals, locks, revision checks and confirmed receipts. Only current-authorized writes create missing protected world directories. Protected-root checks occur on access and private writes; an optional deployment `assertPrivateStorage` callback remains enforced. Production integration additionally gates readiness/writes while any legacy public campaign directory exists. This conservative gate is not cleared merely by copying files.

`planCampaignMigration` is a non-writing operator dry run. Its private manifest includes every nonasset source path, exact binary SHA256 and size, a manifest revision and excluded-asset count. It does not log content or private filenames; callers must keep the manifest protected. Bounds: 4096 visited entries, 2048 copied files, 12 levels, 4 MiB per file and 32 MiB total. PNG/JPEG/WebP/GIF/SVG/video/audio assets remain at original paths for scene compatibility; no licensing or secrecy claim is made for those assets.

`copyCampaignMigration` is an explicit operator-only helper requiring the reviewed manifest revision. Nothing invokes it automatically. It refuses existing destinations and source revision changes. It copies nonassets byte-for-byte without executing scripts, including JSON spatial/manifests and durable receipt artifacts. Every file is verified after copy, the whole source manifest is rechecked before publication, and a protected `.migration-manifest.json` records the copied revision. No source files are moved/deleted, and no destination is overwritten. The ordinary application remains on existing CampaignStorage; this one-time binary copy helper is not another campaign history store.

An incomplete copy retains `.write-lock` and partial evidence, so existing context retrieval fails closed. Cancellation/failure requires operator inspection and separately reviewed cleanup/reconciliation; there is no blind retry or merge into an existing destination. Successful copy removes only its empty lock marker. Local administrators must avoid concurrent filesystem/junction editing: Node cannot provide race-free openat containment on Windows. Application cooperative writers retain their existing locks and live authorization.

Compatibility: source URIs and authenticated Markdown retrieval remain stable; authored binary/supporting files are preserved but never executed by migration. Public originals and asset annotations may still be served by the running Foundry static route. Copying does not resolve that exposure. Restricting/removing public originals requires a separate approved action and actual unauthenticated-route verification after server restart. Existing public-only data cannot be silently used to make protected preparation Ready.

Tests cover missing protected source/no fallback, exact JSON binary copying, unchanged originals, preserved URI, public-source edits ignored, current authority denial, world/role isolation, forbidden public root, authenticated protected writes and pre-copy cancellation. Parent independent validator owns symlink/nooverwrite/mid-copy cancellation review. Live route, loaded protected-root config and runtime migration are not run.
