# Prompt 2 durable native implementation

The reviewed production path uses `DurableNativePreparationComposer` with an authenticated `ExistingWorldDocumentPreparationTransport`. The old review queue remains a private exact-package staging boundary; its legacy `dispatch` intentionally refuses execution.

Each package binds its digest to persisted composition state. The composer obtains a SQLite claim, persists a scene step before dispatch, uses a stable server-owned target ID, then persists and executes individual token steps. Reconnection recovers exact supported-world-document readbacks, including all previously saved receipts; changed/deleted entities fail closed. A post-write interruption reports a partial job and can recover without creating duplicates. Startup claim reset is permitted only during exclusive initialization. Source revisions, trusted human approval, and current GM/world authorization are checked throughout.

The MCP preparation guard checks inactive parent identity immediately before native dispatch. All world-document applies serialize within a world/scene lane. This does not turn Foundry core or unrelated UI writes into atomic transactions; final readback detects changes and live acceptance is not asserted. Whole-scene atomicity is not required.

Private GM notes and traps remain linked in protected campaign records; their text/coordinates are not copied into native public metadata by this composer. Native visibility configuration and executable traps remain separately unresolved. Completion means draft map/token composition; `visibility`, `trapMechanics`, and `liveAccepted` remain false. Nonzero artwork grid origins are explicitly blocked pending a supported calibrated offset mapping.

The local import function accepts only server-trusted hash/license/world/source-scope approvals and verified raster signatures. It writes the verified bytes exclusively to a configured public artwork directory, uses a content-addressed filename, and preserves originals. Explicit approval must establish player-safe artwork; the function does not infer secrecy or license rights. SVG/text and symlink/out-of-scope sources are rejected.

Offline verification: three durable-composition tests (post-write interruption/replay, authorization/source/world/inactive gates, concurrent claims), one local-import test, four existing MCP world-document tests, and one new inactive-parent/identity/concurrency test passed. No runtime mutation, inference, generation, or build-output regeneration occurred. MCP module no-emit checking requires the deployment owner's coordinated shared-package rebuild for the new optional guard type.

Production jobs now use `SqlitePreparationJobStore` on the existing protected server database. Revision compare-and-swap and optional one-time read-only JSON import occur inside `BEGIN IMMEDIATE` transactions. An interrupted transaction rolls back automatically on database reopen; no job claim file requires deletion. Three additional tests cover independent connections/stale revisions, import preservation, and an actual child process exiting with an uncommitted transaction followed by successful reopen/resume. The legacy file store retains an exclusive write claim for offline compatibility; it never steals crash-left claims and is not the production job store.

Foundry v14 native map schema was audited against the installed `App/common/documents/scene.mjs` and `level.mjs`. Scene map images are embedded Level `background.src`; transforms are Level `textures`, with a stable 16-character Level ID and Scene `initialLevel`. Scene `background` is a nonenumerable compatibility shim and is not dispatched or expected in `toObject()` readback. Readback requires every requested Level field and exact Level identities/count while permitting schema-populated defaults. Two representative-v14 tests cover the bridge and native MCP handler, including absence of a top-level background field and detection of a changed image. Native offset changes remain blocked rather than guessed: scene dimensions subtract `shiftX/Y` from scene origin, so any nonzero mapping must account for artwork, native geometry and viewport boundaries together.
