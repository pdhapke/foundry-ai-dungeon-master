# Ordinary DM conversation and exact action review

Phase 5 panel subtask, October 1, 2026. This work consumes the independently validated Phase 3 campaign contract. It does not change hooks, automatic triggers, shared contracts, deployment settings, or live Foundry state.

The ordinary ChatKit composer is the DM conversation. Ask DM and Resolve Action are removed from the rendered toolbar; the existing optional programmatic shortcuts remain compatible. The panel keeps cancellation, connection/sign-in/status, model selection, and proposed-action review. Conversational tips cover campaign setup, later preparation, and character actions without selecting an identity or mode. The ready message identifies every message as a DM conversation and avoids claiming deployment privacy.

Review proposed actions loads both existing native-action confirmations and a separate campaign proposal list. Native private-note confirmation remains compatible. Campaign summaries have only View exact campaign changes; they cannot approve. Opening a proposal requests its complete exact view from the authenticated `/chatkit/actions` endpoint with kind campaign and the current thread ID.

Before enabling approval, the browser verifies schema/version, current world/user/thread, complete-review and confirmation flags, absence of truncation, file count/path uniqueness, before/after text presence, SHA-256 before/after hashes, expected revisions, canon status, mandatory overview/index, and the stable full review digest. The digest covers all ordered complete review files and their metadata with the authoritative scope and title, matching the validated server contract. Any missing/tampered/truncated/oversize view has no decision controls. Model-authored names, file contents, and instruction-like strings remain text, never executable HTML or instructions.

The panel renders every file open with its full before and proposed contents, path, canon transition, expected prior revision, resulting hash, and proposal digest. Scrolling/wrapping changes presentation without removing bytes. Approve these exact campaign changes sends the displayed proposal ID/digest/thread; Reject campaign changes and Cancel campaign proposal use the same frozen binding. All decision buttons disable during dispatch. Expired approval is disabled, including a click-time expiry check. An error leaves decisions disabled and asks the user to refresh and inspect instead of inviting a blind retry.

Pending explicitly means a saved draft, not approved canon. Drafting/dispatching/uncertain outcomes require inspection. Verified campaign commit is shown only for completed status plus a completed receipt matching proposal ID, digest, world, and every exact file revision/sourceHash. Completed status without its matching receipt is reported as unavailable evidence. A decision refreshes the exact persisted proposal rather than inferring completion from assistant narration or the click itself.

Thread changes, cancellation, and panel close invalidate review generations and abort campaign listeners. Late review responses cannot restore an obsolete view. Captured thread identity prevents native or campaign stale buttons from sending decisions to another thread. The panel also refuses authenticated requests after its world/user changes, requiring reopening; hooks and trigger world-transition handling belong to the separate Phase 5 integration owner. Reopening restores the owner-scoped ChatKit conversation and fetches current durable review state on request. Review refresh keeps the mounted composer/frame intact.

Independent validation found and repaired a cancellation race during ChatKit readiness. Active trigger waits now race an explicit cancellation signal; generation/world/component/thread checks run after every awaited mount, readiness, thread HTTP response/body, component thread selection, and custom action. A cancelled trigger cannot initiate a later thread create, persist its late response, or send an action when an ignored provider or component finally resolves. An already-dispatched server request can still have an uncertain effect; cancellation does not prove rollback. Authenticated inference also checks cancellation after its asynchronous body hash and before HTTP dispatch. Late programmatic thread-selection events from a cancelled generation cannot replace a newer user conversation. Separate mocked regressions cover readiness, HTTP/body, selection, close, and reopening.

Changed paths include application.ts/application.test.ts, new campaign-review.ts/campaign-review.test.ts, application.hbs, and ai-dungeon-master.css. No server authoring contract was changed. The original component/helper checks passed; independent cancellation and owner-pointer failures were repaired and revalidated in [panel revalidation](solo-dm-panel-revalidation.md). Captured mount generation/component/owner guards and owner-scoped pointer keys prevent stale events from overwriting another world/user's conversation. Component checks cover exact full text/digest-bound decisions, receipt truthfulness, no summary approval, truncated reviews, cancellation/thread ownership, native-note confirmation, reopen and HTTP stream cancellation.

These are mocked DOM/ChatKit tests and browser crypto checks, not proof of loaded Foundry UI or live model use. Independent panel validation is a separate required gate. Production campaign persistence remains fail closed because the serving privacy boundary is not verified. Actual model, Foundry reload, world/scene switching, and deployment privacy require their separately authorized live acceptance gates.
