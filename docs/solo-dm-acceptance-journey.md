# Joined deterministic acceptance journey

`server/src/chatkit/solo-dm-acceptance.test.ts` runs one controlled journey through the actual authenticated TypeScript adapter, campaign actions, trusted discovery/runtime, native dice action service, filesystem and SQLite. The scripted assistant and MCP client are fixtures. No billable model call, live Foundry request, production resource or configuration change occurs.

The journey creates structured overview/index/location resources through `campaign_propose`; verifies canon remains missing after assistant narration and a forbidden model-side approval attempt; reads the complete browser review with each before/after hash and batch digest; supplies the explicit human approval; and verifies completed receipts and exact persisted file bytes. It then starts a separate preparation turn, reads revision tokens, proposes revised resources, verifies old canon stays intact until approval, and commits the reviewed revisions.

A later play turn receives the revised guaranteed overview and the explicit off-scene party actor rather than the arbitrary on-scene NPC. It retrieves indexed location sections, verifies their hashes against the actual persisted file, and constructs controlled narration solely from sections marked narrationAllowed. The malicious GM-only section stays inaccessible to that narration projection. Its instruction to execute a quarantined provider mutation cannot make that tool discoverable or create an executable grant; an invented grant is denied and the provider mutation is never called.

The same play turn discovers the reviewed dice semantic facade, loads its schema/grant, executes it, obtains a validated completed durable receipt and replays the exact request without a second MCP dice call. A reconstructed campaign service and a fresh later adapter turn recall the approved preparation, matching source hash and persisted dice result.

Evidence: joined journey1/1 PASS, scoped ESLint PASS, server TypeScript check PASS. Existing independent storage/campaign/catalog/panel/trigger suites separately cover their fault, revocation and cancellation boundaries; this test adds the connected success path rather than claiming those separate tests are a live conversation.

Limitations: the human approval is a test driver action, the narration is a controlled fixture projection and the MCP result is fabricated. This proves application contracts and durable fixture state, not model compliance, real dice behavior, Foundry hooks, remote marker propagation or deployment privacy. The temporary storage fixture explicitly supplies a privacy callback for its isolated filesystem; production campaign persistence remains fail-closed. Live acceptance requires approved isolated fixtures/reloads/world switching and an explicit model-use budget, plus direct-file privacy verification.
